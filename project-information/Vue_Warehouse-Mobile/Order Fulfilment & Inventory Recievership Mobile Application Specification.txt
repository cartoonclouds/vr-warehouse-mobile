
Order Fulfilment & Inventory Recievership Mobile Application Specification
==========================================================================
[Samsung Galaxy S8 Tab]





IDEAS [to be made coherant] -- MOST IDEAS WILL NEED A "JUSTIFICATION" SECTIONS
~~~~~~~~~~~~~~~~~~~~~~~~~~~

- Don't hardcode labels/text - allow John to open txt file to change as will

- After viewing available picks to choose - filter all others out, removes distractions, they only should be doing & contentrating on one tasks at a time (however provide icon to show again, ask M/D thoughts if resonable)

- Simple, large, easy to use, icons

- UI/UX (by the people who use it everyday), get THEIR IDEAS/SUGGUESTIONS/IMPROVEMENTS! ie, whats a common mistake that happens unintentionally (and suggestions by them on how to stop it happening?), what information is on the tablets that they (the pickers) never use/read ALSO what they commonly have to ask for/go to a PC?

- Simplify login page by only showing available features depending on user/roles

- provide fallback recovery - to varying degrees: one pick only? all picks logged in to? 

- different orientation show different info?

- for each product line show: (landscape?)
	* Image of product
	* Name
	* Barcode / Carton Barcode
	* Quantity to Pick (Quantity in location, after scan also show qty which should be left)

- shrink/hide scanned items

- different view options : GRID VIEW \ LIST VIEW : larger,box view \ line, detailed view

- provide different modalities with change - quick vibrate if ok, two vibrates if problem

- items MUST ALWAYS have a location - when picking scanning from location to "picking", on packing when scanning carton to "carton" (keep track of location)	
	item location > picking trolly (have an ID?) > packing station > carton

- make obvious when items scanned correctly, wrong item, wrong location (show somewhat at a glance difference to user) - turn green for correct location and green for the correct items, if both good slide down.
	ie, https://www.youtube.com/watch?v=y3oaVwPtq8E		

- for warehouse roles provide more grandular data re: what each picker is doing at that point in time (what orders on the go?, up to what point they are with them? daily statistics, etc.), with alerts after whatever defined thresholds (ie, with # of orders and pickers time delays) or internet is slow/down in there, [maybe] printer issues [if can talk with node-print], scheduled pickup reminders by customer or courier (if we know when they'll be in) -- some of these may have to be configurable to receiving alerts no *every* time -- 

- do picking orders now need to be 'grouped' (by that i mean on the same page just sepeerated)





- Research, describe & explain possible improvements to the methodology:
	~ Discrete Order Picking, 
	~ Zone Picking, 
	~ Batch Picking, 
	~ Cluster Picking, 
	~ Wave Picking, ++++
	(https://www.newcastlesys.com/blog/bid/329992/7-Excellent-Methods-to-Improve-Picking-and-Packing-Efficiencies)
  ... and possibly provide the ability to implement. IE, easier prioritising from office (and easier to see) or providing Batch Picking
